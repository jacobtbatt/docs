---
title: "Status Webhooks"
description: "Receive real-time notifications when a Thnks sent by your team changes status."
---

Status webhooks notify your systems as each Thnks moves through its lifecycle. Once a webhook URL is configured for your team, Thnks sends a JSON payload to that URL every time a Thnks sent by a team member changes status.

## Set up a webhook

<Steps>
  <Step title="Prepare an endpoint">
    Stand up a URL that accepts HTTP POST requests with a JSON body. Integration platforms such as Workato or Zapier can generate one with a webhook (catch hook) trigger.
  </Step>
  <Step title="Request activation">
    Have a Thnks Admin email [developer@thnks.com](mailto:developer@thnks.com) with your endpoint URL and the team(s) whose events you want to receive. Webhooks can cover a single team or a team and all of its sub-teams.
  </Step>
  <Step title="Test the integration">
    Send a Thnks as a team member, trigger a status change (for example, open the gift email), and confirm your endpoint receives the notification.
  </Step>
</Steps>

## Events

A webhook is sent when a gift transaction moves to any of these statuses.

| Status | Description |
| --- | --- |
| Sent | Sent to the recipient |
| Delivered | Successfully delivered |
| Undelivered | Could not be delivered |
| Opened | Opened by the recipient |
| Redeemed | Redeemed by the recipient |
| Re-gifted | Passed along to someone else |
| Donated | Value donated by the recipient |
| Replaced | Exchanged for a different Thnks |
| Expired | Expired before being opened or redeemed |

<Note>
  Webhooks are sent per gift transaction. A gift bundle generates one webhook for each gift in the bundle.
</Note>

## Status values

### `tracking_status`

| Value | Description | Events |
| --- | --- | --- |
| `sent` | Sent; the recipient has not acted on it | Sent, Delivered, Expired |
| `received` | The recipient opened or acted on the Thnks | Opened, Redeemed, Re-gifted, Donated, Replaced |
| `undelivered` | Could not be delivered | Undelivered |

### `receiving_status`

| Value | Description | Events |
| --- | --- | --- |
| `new` | Sent; delivery not yet confirmed | Sent, Undelivered |
| `delivered` | Delivered | Delivered |
| `opened` | Opened by the recipient | Opened |
| `accepted` | Redeemed by the recipient | Redeemed |
| `re_gifted` | Passed along to someone else | Re-gifted |
| `donated` | Value donated | Donated |
| `replaced` | Exchanged for a different Thnks | Replaced |
| `expired` | Expired before being opened or redeemed | Expired |

<Tip>
  When `receiving_status` is `new`, check `tracking_status` to tell a Sent event from an Undelivered one.
</Tip>

## Responding to webhooks

Return an HTTP `200` response to acknowledge receipt.

<Warning>
  Thnks does not retry failed deliveries. If you think you are missing notifications, contact [developer@thnks.com](mailto:developer@thnks.com) and we can check the delivery log.
</Warning>
